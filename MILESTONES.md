# Milestones — Lumen (lumen-tv)

Spec: `BRIEF.md`. Each milestone stops for Laith to test on the TV before the next starts. Order: root install helper + Kodi to Store (M5.3) → M5.5 → M6; M5.2 on hold (see scope changes).

## Scope changes
- **2026-10-25, Kodi becomes a Store app (Laith):** Kodi is redundant now. It stops being a default tile and the crash rescue, comes off pitv, and returns only as a Store entry (apt, through the root helper). This folds into M5.3, so the helper's Gate runs on a real package: Kodi is uninstalled from the Store with the PIN at the M5.3 TV test. The crash rescue becomes a tty1 console login, and `install.sh --revert` becomes a console boot. Until RetroArch lands in M5.5, Laith has no retro games (GB/GBA/DS ran in Kodi's RetroPlayer). `~/.kodi`, `~/roms` and all saves stay on the Pi.
- **2026-10-25, M5.2 on hold; Spotify app (Laith):** M5.2 (Steam Link in the background) is paused. Laith wants to live with close-on-exit for a while first; the spike was stopped after one finding (Steam Link ships SDL3 with HIDAPI and could read the DualSense through `/dev/hidraw*`, so an evdev grab alone may not block it) and its Pi changes were undone. The root install helper and M5.5 go next. In M5.5, Spotify means the full Spotify app (lyrics view, karaoke-style use, controllable as a Connect device), not only a headless Connect receiver.
- **2026-10-24, AirPlay tile (Laith):** a default AirPlay (screen mirroring) tile joins M5.1 next to YouTube, instead of waiting for M5.5's Store entry. Pi-tv's UxPlay setup (`../config/airplay-mirror`, `uxplay.service`) is built for Kodi: it draws with `kmssink` straight to DRM and runs as a unit that `Conflicts=kodi.service`, while `lumen.service` conflicts with `uxplay.service`. Inside Lumen it has to run as an app in the labwc session with a Wayland video sink.
- **2026-10-22, found in daily use (Laith):** (1) Lumen has no way to power off, reboot or restart from the couch. A Power menu joins M5, since M5 makes Lumen the boot default and there is no other way out without SSH. (2) Home closes Steam Link (BRIEF §5/§11: close-on-exit + exclusive); Laith wants it to stay running like Jellyfin. This changes BRIEF's lifecycle for Steam Link and becomes M5.2, after a spike (it reads the pad directly and decodes the stream in software, so keeping it alive has costs). (3) YouTube becomes the first milestone after M5 (M5.1), ahead of the root helper and the rest of M5.5. M5's T12(d) still checks the BRIEF behaviour (Steam Link closes on Home) until M5.2 changes it.
- **2026-10-20, controller in web apps (Laith, found at the M4.5 TV test):** Jellyfin web (Chromium) ignores the DualSense (only its touchpad moves the pointer). M4.5 adds: while a `type = "url"` app is in front, Lumen turns the pad's actions into keys through its own uinput keyboard (arrows, Enter, Back, play/pause), the way the TV remote's keys reach apps. Steam Link and Kodi keep reading the pad directly. Also found: pairing from the panel paired without bonding (no agent registered), so BlueZ rejected the pad's HID link; Lumen now holds a default pairing agent while the Bluetooth panel is open.
- **2026-10-20, more Store apps + install for other people (Laith):** two new milestones come after M5. **M5.5** fills the Store with apps that suit a TV launcher and media box. **M6** makes Lumen something other people can install and use on their own Pi: no Laith-specific values, prebuilt releases, a first-run setup, and docs for strangers. BRIEF §8 kept v1 to Laith's own box; both milestones go beyond v1.
- **2026-10-19, store root policy + resolution switch (Laith):** M4's store runs only user-level steps (flatpak `--user`); apt entries show their commands to run over SSH. A new milestone (after M4.5, before or folded into M5, ordering TBD) adds a root-owned install helper: a small Rust daemon on a Unix socket, an on-screen PIN pad in Lumen, the PIN checked by the helper (argon2-hashed, root-only file, rate-limited), apt run with an argument list and `--` (never a shell string), and only packages on a **root-owned allowlist on the Pi** (never trusted from the downloaded manifest, which anyone controlling the repo or network could change). This is milestone M5.3 below. M5 gains a resolution switch in Settings (1080p60 / 4K60, saved and re-applied whenever HDMI-A-1 reappears, e.g. after the TV power-cycles), replacing the optional O.1 fix.
- **2026-10-13, Plex dropped; red = Home (Laith):** Plex is removed from the shipped apps (Jellyfin covers it), so the Gate no longer counts Plex. The LG basic remote never forwards Home/Settings/Exit or a held Back (the TV opens its own menu), so the remote's **red** key is Home; long-press Back is impossible on this TV. The Kodi tile runs with its own CEC off so Lumen keeps the remote.
- **2026-10-13, TV remote into M3.5; controllers + Bluetooth into a new M4.5 (Laith):** the regular LG TV remote (HDMI-CEC) is un-docked and becomes part of M3.5: it must drive Lumen, Settings and the apps, with a working Home. Game controllers (PS5 DualSense, Xbox) and a Bluetooth pairing screen in Settings (so pairing needs no terminal) move out of M5 into a new M4.5, built when the Settings screen grows. M5's input polish keeps only what is left after that.
- **2026-10-08, UI stack (Laith):** Slint 1.18 (femtovg renderer, winit backend under labwc) replaces Tauri 2 + Svelte + WebKitGTK, which BRIEF §2 names. Reason: the Slint spike (tag `spike-slint-2026-10-08`, `spike-slint/REPORT.md`) hit 60.0 fps / 0.1% slow frames at 1080p60 with no focus flash, vs WebKit's 56.6 fps / 9.8%. All Rust (input, registry, store, platform traits) is unaffected; the BRIEF §3 "Tauri events / commands" bridge becomes Slint callbacks + `slint::invoke_from_event_loop`. Output stays 1080p60 (live gradients and shadows were too slow at 4K on the Pi 5 GPU with every toolkit; see the 4K entry below).
- **2026-10-08, 4K output (Laith):** 4K60 works after baking the hero backdrops, tile faces and focus shadow into images on the CPU (`src/bake.rs`, merged from `exp/baked-hero`), so the fill-rate-bound GPU draws one backdrop layer. Bench on main (0abbe64): 4K60 59.7 fps, 0.4% > 25 ms, p95 17.4 ms (was 27.8 fps); 1080p60 60.0 fps, 0.1%, p95 17.1 ms. Default stays 1080p60 for now; `LUMEN_MODE=3840x2160@60` selects 4K.
- **2026-10-08, M2 gate cut (Laith):** M2 closes on the TV remote alone. The real controller (PS5 DualSense over USB/BT; `playstation.toml` already maps it) and keyboard checks move to M5 polish.
- **2026-10-09, input layer docked (Laith; remote part superseded 2026-10-13, see above):** the keyboard is the control for development; the input layer stays as built in M2 and gets no new work. Parked until an "Input polish" pass in M5: controller (PS5 DualSense) and the rest of the M2 gate. M3 keeps only what launching needs: while an app is in front, Lumen acts on Home alone (keyboard Home/F1 per `keyboard.toml`).
- **2026-10-09, icons + debug Settings earlier (Laith):** app icons are drawn on tiles in M3 (BRIEF's `icon` field), not M5. A Settings/diagnostics screen moves from M5 into a new M3.5, to make debugging on the TV easier.
- **2026-10-08, license (Laith):** Lumen is published under GPLv3, since Slint's royalty-free license excludes embedded systems.
- **2026-10-08, fallback web clients:** `fallback_url` (Jellyfin/Plex web in kiosk mode) can no longer open in a Tauri webview window. It needs a separate kiosk browser (Cog/WPE or Chromium); the choice is made in M3, and only if no native client works.

## M1 — Skeleton + perf check ✅ (2026-10-06)
Tauri 2 + Svelte 5/Vite, fullscreen under labwc via `lumen-test.service`, static 12-tile row, frame-time overlay + 30 s bench.
**Gate (revised 2026-10-06 by Laith):** ≥ 55 fps average during the 30 s hold-Right bench at 1920x1080 output, and Laith judges it smooth on the TV. Original gate (≥ 55 fps and < 5% frames > 25 ms at native 4K) failed.
**Result:** 4K = 9.4 fps (GPU fill rate; CPU rendering and DMA-BUF-off are worse). 1080p60 output (wlr-randr in `session/start-lumen.sh`) = 55.9 fps, 16% slow frames, ~1 dropped frame per focus change even with all effects off (fixed WebKit per-change cost). Removing the tilt spring-back and title slide fixed most visible glitching; pre-painting stacked backdrops made it worse (12 full-width layers). The focus-change flash/snap was fixed with "hold" animations (56.6 fps, 9.8% slow).
**Slint spike (2026-10-08, same bench):** femtovg 1080p60 = 60.0 fps, 0.1% > 25 ms, p95 17.6 ms, no flash/snap ("looks smooth, no flashes"). Skia (OpenGL) 1080p60 = 55.2 fps / 4.4%. 4K: femtovg 27.6 fps, Skia 14.1, WebKit 9.4 (fill-rate bound; idle redraw alone is 31 fps). Led to the stack change above.

## M5.2 — Steam Link stays running in the background (on hold, 2026-10-25)
Home leaves Steam Link running (like Jellyfin) instead of closing it, so going back is instant and the stream doesn't reconnect. Steam Link reads the pad itself and decodes the stream in software, so a plain keep-alive could (a) send pad presses meant for Lumen into the game and (b) keep burning CPU and drop Lumen below 60 fps. Start with a short spike on the Pi measuring both, then pick one: keep-alive + grab the pad away from Steam Link while Lumen is in front (EVIOCGRAB in Lumen's reader); keep-alive + pause the process (SIGSTOP/SIGCONT) while hidden, if the stream survives it; or keep closing it but make relaunch auto-connect to the last host. `exclusive = true` (closing Jellyfin on launch) is revisited at the same time.
**Gate:** (confirmed by Laith 2026-10-24) from a game streaming in Steam Link, PS/red goes to Lumen and selecting Steam Link again shows the same game within 3 s with no reconnect screen (same PID); 30 s of pad presses on Lumen's Home reach nothing in the game; the Home bench with Steam Link in the background stays ≥ 59 fps / < 2% slow; Steam Link still exits cleanly when quit from inside it.

## M5.3 — Root install helper (PIN) + Kodi as a Store app ✅ (2026-10-26)
Lets the Store install and remove apt packages from the couch without SSH (scope change 2026-10-19). A small root-owned Rust daemon, `lumen-helper`, listens on a Unix socket (`/run/lumen-helper.sock`, root:lumen-helper 0660, systemd socket activation, exits after 60 s idle). Lumen shows an on-screen PIN pad (d-pad grid, 4–8 digits, dots) for `root: true` Store entries and sends the PIN with the request; the helper checks it against an argon2id hash in a root-only file (`/var/lib/lumen-helper/pin`, 0600) and rate-limits wrong PINs (5 wrong → 60 s lock, doubling to 1 h max, persisted in `/var/lib/lumen-helper/attempts.json`, reset on success). The request names a Store app id, never a package: the helper looks the id up in the root-owned allowlist on the Pi (`/etc/lumen-tv/helper-allowlist.toml`) and runs `/usr/bin/apt-get` with an argument list ending in `--` and the allowlisted package names (never a shell string, cleared environment, `DEBIAN_FRONTEND=noninteractive`, dpkg lock timeout), streaming output back to the Store's progress view. Uninstall removes only the entry's listed `remove` packages (no autoremove/purge; Laith 2026-10-25). The downloaded manifest is never trusted for package names; an id not on the allowlist is refused and the Store falls back to today's "run over SSH" text. The helper binary is installed as a root-owned copy (`/usr/local/libexec/lumen-helper`), never run from `~/lumen-tv/target`. The PIN is first set over SSH (`sudo /usr/local/libexec/lumen-helper set-pin`). Install steps go through `session/install.sh --helper` (dry run by default). Steam Link, AirPlay, Kodi and a `root-test` entry (package `sl`) move onto the helper. Decisions D1–D8 approved by Laith 2026-10-25.
**Kodi becomes a Store app:** Kodi is no longer a shipped default tile (`config/apps/kodi.toml` goes; `.shipped` already lists `kodi`, so nothing re-adds it). It becomes a `root: true` Store entry whose allowlist set holds only Kodi's own packages; uninstall is `apt-get remove`, never purge, and never touches `~/.kodi`, `~/.kodi-tile` or `~/roms`. ## M6 — Easy install for other people
Anyone with a Pi 5 and a TV can install Lumen without knowing Laith's setup.
- **No Laith-specific values in shipped files:** the user `laith` (`session/lumen-test.service`, `session/sudoers-lumen`, `src/apps.rs`) and the rack's Jellyfin URL `192.168.5.174` (`config/apps/jellyfin.toml`, `store/manifest.json`) become per-install settings or first-run answers.
- **Prebuilt releases:** a GitHub Actions build for arm64 (native arm runner) publishes a `.deb` on each tag, so nobody builds Rust on their Pi. One documented install command on stock Raspberry Pi OS Lite 64-bit sets up packages, groups/udev, the labwc session, autologin and units for whatever user runs it.
- **First-run setup on the TV:** language-free basics with the remote: pick resolution, test the remote/controller, optionally enter a Jellyfin/Plex server URL, choose which default tiles to keep.
- **Updates + removal:** update from a new release (one command, or from Settings) without losing the user's apps, input overrides or settings; a documented uninstall that returns the Pi to a console boot.
- **Docs:** README for strangers (requirements, install, first run, remotes known to work over CEC, troubleshooting, adding an app or a manifest), CONTRIBUTING for new Store entries.
- Decided (Laith, 2026-10-20): **Pi 5 only** for now (no Pi 4 perf work); distribution is **a `.deb` + one install command only**, no flashable image.
**Gate (proposed, needs Laith's confirmation):** on a second Pi 5 freshly flashed with Raspberry Pi OS Lite 64-bit and a user not named `laith`, following only the README: the install command finishes without errors and a reboot lands on Lumen's first-run setup, then Home, within 15 minutes of first boot (not counting flashing); `grep -rn "laith\|192\.168"` over the release package finds nothing; installing a newer release keeps the installed Store apps and settings; the uninstall steps bring back a console login. Best done by someone other than Laith.
